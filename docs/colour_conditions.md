# Colour conditions

The indicators this build derives, and the two arrow rules read on top of them.

Every value below is the **resolved recipe** -- read from the recipe
`python build_charts.py` builds with when it is given no `--config` (`config/nifty.json`) -- through
the very rule objects the build runs. Nothing here is transcribed by hand: this document is
generated by [`tools/write_colour_conditions.py`](../tools/write_colour_conditions.py),
so re-run it after a change and the tables follow the recipe.

* the indicators are the columns written by the steps in `nifty/data/analysis.py`, defined in
  `nifty/signals/series.py`;
* the two arrows are one rule in `nifty/signals/rules.py` read two ways round: the recipe declares
  the green one, and the red one is its `mirrored()` -- derived, never restated;
* the build itself states the same seven conditions for both rules when it runs, so it is the
  live cross-check for this file.

Condition 4 of each rule is the session's own dashboard: the feed's `ce_oi_change` and
`pe_oi_change` for the minute the candle opens in, joined onto the bar by `nifty/data/flow.py`.
A session that ships no dashboard has no such reading, and that one condition is then not
read rather than read as a zero.

## 1. The indicators

Nothing in this table decides anything. The rows are descriptive: they say where two
averages swapped sides, which side they sit on, how long a run is, and how far apart they
were when they crossed. The only thing that decides is the arrow rule in section 2 and its
mirror in section 3, and it reads these columns rather than adding a series of its own.

| Column (bar key) | Holds | What it is | Written by |
|---|---|---|---|
| `sma<p>` | float or blank | the simple moving average of the bar close over `p` candles, summed in integer paise so it is exactly reproducible; blank for the first `p - 1` candles. `<p>` is `2`, `9`, `44` | `series.add_sma` |
| `sma<p>_chg_pct` | float or blank | (this candle's SMA - the previous candle's SMA) / the previous candle's SMA x 100, rounded half-up to `analytics.pct_decimals` = `4`; blank on a session's first candle | `series.add_analytics` |
| `sma<p>_streak_plus` | int | the length of the unbroken run of *rising* changes of that average; `0` when the last measurable change was not rising | `series.add_analytics` |
| `sma<p>_streak_minus` | int | the same for *falling* changes (`0` when the last one was not falling). A rise zeroes this one; a reversal starts a new run at `1`; a change of exactly zero resets both | `series.add_analytics` |
| `sma2_vs_sma9_above_streak` | int | consecutive candles where SMA 2 > SMA 9 **and** the SMA 9 change is positive; anything else resets it to 0 (pair: 2 / 9) | `series.add_direction_streak` |
| `sma2_vs_sma9_below_streak` | int | consecutive candles where SMA 2 < SMA 9 **and** the SMA 9 change is negative | `series.add_direction_streak` |
| `sma2_vs_sma9_cross_direction` | `ABOVE` / `BELOW` / blank | the *strict* crossing of the pair 2 / 9: `ABOVE` when the fast average was below the slow one on the previous candle and is above it now, `BELOW` for the mirror image; blank when the pair stayed on its side, when the two are equal (a tie is never a crossing), and on a session's first candle | `series.add_cross` |
| `sma9_vs_sma44_distance_pct_at_cross` | float or blank | ((SMA 9 - SMA 44) / SMA 44) x 100, read **only on the candle that carries a crossing**, at `analytics.pct_decimals`; blank when there is no crossing, when an average is unavailable, or when the divisor is zero. Pair: 9 / 44 | `series.add_cross` |
| `sma2_vs_sma9_distance_pct_at_cross` | float or blank | the same distance measured on the crossing pair itself (2 / 9); carried for reference -- **no arrow condition reads it** | `series.add_cross` |
| `sma9_vs_sma44_relation` | `ABOVE` / `BELOW` / blank | which side SMA 9 sits on relative to SMA 44 on *this* candle -- a plain comparison, not a crossing, so it holds on every candle both averages exist; blank when they are equal or either is unavailable. Pair: 9 / 44 | `series.add_relation` |
| `ce_oi_change` | integer or blank | the session's dashboard gives one row per minute, and every bar of a minute reads that row: this is the minute's call open-interest change, copied as the feed publishes it. Blank on a session that ships no dashboard | `flow.attach_flow` |
| `pe_oi_change` | integer or blank | the same minute's put open-interest change. The green rule fires only where `pe_oi_change > ce_oi_change`, its mirror only where `ce_oi_change > pe_oi_change` | `flow.attach_flow` |
| `green_arrow` | `0` / `1` | `1` exactly where all seven green conditions below hold, else `0` | `rules.add_signal` |
| `red_arrow` | `0` / `1` | `1` exactly where all seven red conditions below hold, else `0` | `rules.add_signal` |

**The candle's own body** is not a column. `series.bar_color` reads a bar's `open` and
`close` in exact integer paise and returns `green` (close above open), `red` (below) or
`doji` (equal -- a tie, so it belongs to neither colour); the summary's green / red / doji
counts come from there and nowhere else.

**How a run is counted** -- both `sma<p>_streak_plus` and `_streak_minus`, and the pairing
of the two arrow conditions that read them, are kept under `analytics.run_rule`, quoted
from the recipe:

> consecutive: a rise extends the rising run and zeroes the falling one (and vice versa); a reversal starts a new run at 1; a zero change zeroes both

## 2. Green arrow

**Six conditions, all of them required (AND).** The first three are read from the candle
itself, the last three from the candle before it. A blank column is never a hit, and a
session's first candle can never fire because there is no previous candle to read.

| # | Read on | Column in the table | Condition | Recipe key | Value |
|---|---|---|---|---|---|
| 1 | current | `sma2_vs_sma9_cross_direction` | the crossing row reads `ABOVE` | `signal.cross_direction` | `ABOVE` |
| 2 | current | `sma9_vs_sma44_distance_pct_at_cross` | the distance (%) at that cross is `0` to `0.025`, both ends included | `signal.distance_pct_at_cross_min` / `_max` | `0` / `0.025` |
| 3 | current | `sma9_vs_sma44_relation` | the relationship row reads `ABOVE` | `signal.relation` | `ABOVE` |
| 4 | current's minute | `pe_oi_change` + `ce_oi_change` | the dashboard's minute this candle opens in reads `pe_oi_change` **greater than** `ce_oi_change` | `signal.use_flow` (the pair itself is the dashboard's own columns) | `pe_oi_change` > `ce_oi_change` |
| 5 | previous | `sma44_chg_pct` | the SMA 44 change (%) is strictly above `0.0005` | `signal.chg_pct_min` | `0.0005` |
| 6 | previous | `sma9_streak_minus` + `sma9_streak_plus` = `0` | the SMA 9 **falling** run is `7` to `15`, and its rising run is `0` | `signal.streak_minus_min` / `_max` | `7` / `15` |
| 7 | previous | `sma44_streak_plus` | the SMA 44 **rising** run is `7` or more | `signal.streak_plus_min` | `7` |

In the recipe's own words:

> GREEN ARROW, drawn below the bar on the price pane of every timeframe, on the candles where all seven conditions hold (AND); the current candle: SMA 2 vs SMA 9 cross direction is ABOVE, the SMA 9 vs SMA 44 distance (%) at that cross is 0 to 0.025 inclusive, SMA 9 vs SMA 44 reads ABOVE, and the dashboard's minute this candle opens in reads pe_oi_change above ce_oi_change (a session with no dashboard does not read that condition); the previous candle: the SMA 44 change (%) is strictly above 0.0005, the SMA 9 consecutive count is a falling run of 7 to 15, and the SMA 44 consecutive count is a rising run of 7 or more. It marks a candle that has already closed, reads no later bar, and is one of this sheet's two marker rules, each the exact mirror of the other.

The flag ships as `green_arrow` -- `1` on the candles that fire, `0` on every
other -- and the arrow is drawn **below** the bar on the price pane of every timeframe.
`signal.enabled` is `true`.

## 3. Red arrow

**The same six conditions, read the other way round.** Every word is flipped, the distance
window is negated with its ends swapped, the change threshold is negated and its
comparison reversed, and each run is read from the other run's column. The mirror is built
by transform rather than restated, so there is no second set of numbers to keep in step:

| # | Read on | Column in the table | Condition | Comes from (green) | Value |
|---|---|---|---|---|---|
| 1 | current | `sma2_vs_sma9_cross_direction` | the crossing row reads `BELOW` | `signal.cross_direction`, flipped (ABOVE &harr; BELOW) | `BELOW` |
| 2 | current | `sma9_vs_sma44_distance_pct_at_cross` | the distance (%) at that cross is `-0.025` to `0`, both ends included | `signal.distance_pct_at_cross_min` / `_max`, negated with the ends swapped | `-0.025` / `0` |
| 3 | current | `sma9_vs_sma44_relation` | the relationship row reads `BELOW` | `signal.relation`, flipped (ABOVE &harr; BELOW) | `BELOW` |
| 4 | current's minute | `ce_oi_change` + `pe_oi_change` | the dashboard's minute this candle opens in reads `ce_oi_change` **greater than** `pe_oi_change` | the green pair, swapped: `pe_oi_change` above `ce_oi_change` becomes `ce_oi_change` above `pe_oi_change` | `ce_oi_change` > `pe_oi_change` |
| 5 | previous | `sma44_chg_pct` | the SMA 44 change (%) is strictly below `-0.0005` | `signal.chg_pct_min`, negated, and the comparison reversed to *below* | `-0.0005` |
| 6 | previous | `sma9_streak_plus` + `sma9_streak_minus` = `0` | the SMA 9 **rising** run is `7` to `15`, and its falling run is `0` | `signal.streak_minus_min` / `_max`, read from the opposite run | `7` / `15` |
| 7 | previous | `sma44_streak_minus` | the SMA 44 **falling** run is `7` or more | `signal.streak_plus_min`, read from the opposite run | `7` |

In the recipe's own words:

> RED ARROW, cross direction BELOW, relation BELOW, distance -0.025 to 0 inclusive, change strictly below -0.0005, fast falling run 7 to 15, slow rising run 7 or more

The flag ships as `red_arrow` and the arrow is drawn **above** the bar.
`signal.red_arrow` is `true` -- a switch, not a threshold: `false` keeps the
column, always `0`, and draws no mark. There is no red threshold in the recipe to edit, and
a key that names one is refused rather than ignored.

## 4. How the red rule is derived, key by key

| Green value | Red value | Transform |
|---|---|---|
| `signal.cross_direction` = `ABOVE` | `BELOW` | `flipped_word` (ABOVE &harr; BELOW) |
| `signal.relation` = `ABOVE` | `BELOW` | `flipped_word` |
| the flow pair: `pe_oi_change` above `ce_oi_change` | `ce_oi_change` above `pe_oi_change` | the two sides swapped -- this comparison mirrors by exchanging its operands |
| `distance_pct_at_cross_min` = `0` | `-0.025` | the green **max**, negated |
| `distance_pct_at_cross_max` = `0.025` | `0` | the green **min**, negated; a negated `0.0` is folded back to `0.0`, so no rule sentence and no payload carries a `-0` |
| `chg_pct_min` = `0.0005` | `-0.0005` | negated, and `>` becomes `<`: strictly above the threshold becomes strictly below its negative |
| `streak_minus_min` / `_max` = `7` / `15` | `7` / `15` | unchanged; the red rule reads that window off `sma9_streak_plus` instead of `sma9_streak_minus` |
| `streak_plus_min` = `7` | `7` | unchanged; read off `sma44_streak_minus` instead of `sma44_streak_plus` |
| `red_arrow` = `true` | -- | a switch, not a threshold |

Both rules read the same set of columns -- `sma2_vs_sma9_cross_direction`, `sma9_vs_sma44_distance_pct_at_cross`, `sma9_vs_sma44_relation`, `sma44_chg_pct`, `sma9_streak_plus`, `sma9_streak_minus`, `sma44_streak_plus` -- which is what lets their
per-condition tallies be read side by side under one set of names.

## 5. Where to change any of it

All of these live in [config/nifty.json](config/nifty.json) (the same keys exist in
[config/nifty.toml](config/nifty.toml)), and `--set section.key=value` overrides one for a
single run. A key left out keeps its built-in default, so a short recipe is a valid recipe.

| Recipe key | Now | What changing it does |
|---|---|---|
| `signal.enabled` | `true` | whether the green arrow is drawn at all; the column stays, carrying `0` |
| `signal.cross_direction` | `ABOVE` | the word condition 1 must read |
| `signal.relation` | `ABOVE` | the word condition 3 must read |
| `signal.distance_pct_at_cross_min` / `_max` | `0` / `0.025` | the window condition 2 must fall inside, both ends included |
| `signal.chg_pct_min` | `0.0005` | the threshold condition 4 is compared strictly against |
| `signal.streak_minus_min` / `_max` | `7` / `15` | the window condition 5 must fall inside |
| `signal.streak_plus_min` | `7` | how long the run condition 6 demands |
| `signal.red_arrow` | `true` | whether the mirror is drawn; the thresholds it reads are the green ones either way |
| `signal.fast_period` / `slow_period` | `9` / `44` | the pair whose runs and change the previous candle contributes; left unset they are taken from `[relation]` |
| `cross.fast_period` / `slow_period` | `2` / `9` | the crossing pair condition 1 reads |
| `cross.distance_from_period` / `distance_to_period` | `9` / `44` | the pair behind the distance column condition 2 reads |
| `relation.fast_period` / `slow_period` | `9` / `44` | the pair behind the relationship row condition 3 reads |
| `analytics.periods` | `2`, `9`, `44` | which averages exist to be read; every period a rule names must be among them |
| `analytics.pct_decimals` | `4` | the precision every percentage is *compared* at: the bounds become scaled integers, so a value sitting exactly on one falls on the side the operator says |
| `signal.rule` / `red_rule` | written from the values above | override the two sentences only, never a threshold |

## 7. What the rules guarantee

* **No future bar is read.** The three conditions on the current candle read that candle
  only, and the three on the previous candle read the one before it. Nothing later.
* **A session starts clean.** A session's bars begin at its own first candle, so no
  crossing, run or arrow is ever carried across a session boundary.
* **A blank column is not a hit.** An unavailable average, a missing previous candle or a
  zero divisor produces a blank, and a blank never satisfies a condition -- it is not read
  as a zero worth counting.
* **One definition, two rules.** Both arrows run through one `GreenArrowRule.hits`, and the
  per-condition funnel and the rule sentences are generated from that same object, so the
  tallies, the sentences and the arrows cannot describe different rules.
* **Every arrow marks a candle that has already closed.**
